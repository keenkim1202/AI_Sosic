## 요약

에이전트 메모리 글은 대개 "무엇을 기억할까"를 다루는데, 이 글은 **무엇을 버릴까**를 다룸. 논지 한 줄로 요약하면 이거임.

> 네 에이전트의 문제는 잊어버린다는 게 아니라, **의도적으로 잊지 않는다**는 것.

Stanford, Microsoft, Anthropic, Nvidia 네 곳의 연구를 하나씩 렌즈로 삼아 6개 테마 15단계로 정리함. 수치가 구체적이라 건질 게 많음.

## 네 개의 렌즈

각 연구소가 이 시스템에 대한 서로 다른 질문 하나에 답함. 네 개를 동시에 들고 있는 게 기술임.

| 연구소 | 질문 |
|---|---|
| **Stanford** | 기억하는 데 얼마가 드는가 |
| **Microsoft** | 무엇이 보관할 가치가 있는가 |
| **Anthropic** | 무엇을 보관할지 누가 통제하는가 |
| **Nvidia** | 하드웨어의 어디를 때리는가 |

## 시작: 저장소를 "메모리"라고 부르지 말기

벡터 DB 켜고 히스토리 밀어넣고 top-k 검색하면 에이전트에 메모리를 줄 수 있음. 그게 통하는 건 히스토리가 컨텍스트 윈도우를 넘기 전, **쓰기 경로 비용이 쿼리 비용을 넘기 전**, 아무도 치우지 않는 낡은 상태로 저장소가 차기 전까지임.

진짜 메모리는 저장소가 아니라 **대사(metabolism)를 가진 시스템**임. 들어올 때 에너지를 먹고, 세션마다 자라고, 아무것도 가지치지 않으면 썩고, 6개월 전에 참이었지만 지금은 틀린 기억을 내놓음.

## Stanford, 짓기 전에 값을 매겨라

**쓰기 경로로 시선을 옮김.** Stanford가 에이전트 메모리에 대한 첫 실제 시스템 연구를 했고, 결과가 불편함. **비용은 네가 보는 곳에 없음.** 모두가 사용자가 느끼는 쿼리 지연시간을 보는데, 실제 청구서는 원시 히스토리를 저장 레코드로 바꾸는 **구축 단계**에서 나옴. 사용자는 그걸 못 봄.

**정확도가 아니라 정답당 에너지를 측정함.** 정확도는 청구서를 가림. 정답 수로 에너지를 정규화하면 **정확도가 동일한 두 시스템이 47배 차이**로 갈림. 같은 과제, 같은 GPU, 어떤 정확도 벤치마크도 절대 보여주지 않을 47배 격차.

> 앞으로 모든 메모리 시스템은 숫자 두 개를 받음. 품질, 그리고 정답당 비용. 첫 번째를 두 번째 없이 인용하지 않음.

**최고의 시스템은 없으니 비용을 고름.** Stanford는 메모리를 네 계열로 분류함. 원시 컨텍스트, 평면 검색, 구조화 추출, 완전 에이전틱. **구축 비용, 쿼리 속도, 정확도를 동시에 이기는 건 하나도 없음.** Mem0 같은 시스템은 0.1초 안에 답하지만 구축에 수천 초를 냄. 어휘 인덱스는 즉시 구축되지만 쿼리가 느리고 뭉툭함. 그래서 Memory Engineer는 최고의 시스템을 고르지 않고 **어떤 비용을 낼지 의도적으로 고름.**

## Microsoft, 무엇이 보관할 가치가 있나

**로그가 아니라 사실과 스킬을 저장함.** Microsoft의 PlugMem 연구는 불편한 결과에서 시작함. **에이전트에 원시 메모리를 더 주면 더 나빠질 수 있음.** 히스토리가 쌓이고 검색이 익사하고, 에이전트가 중요한 한 줄을 찾겠다고 트랜스크립트를 헤치며 주의력을 태움. 해법은 인간 기억에서 훔쳐옴. 우리는 사건을 재생하지 않고 **거기서 뽑아낸 사실과 스킬을 보관함.**

**크기가 아니라 효용으로 판단함.** 사실과 스킬로 저장했더니 **범용 메모리 모듈 하나가 세 과제에서 목적 설계된 것들을 이겼고 토큰도 덜 썼음.** 지표로 옮기면 이렇게 됨. 저장에 성공한 양이 아니라, **컨텍스트 토큰당 에이전트에 도달하는 의사결정 관련 정보량**을 최적화함. 밀도가 부피를 이김, 매번.

**모델이 자기 컨텍스트를 관리하게 함.** Microsoft의 Memento는 메모리를 모델 안으로 밀어넣음. 블록 단위로 추론하고, 스스로에게 밀도 높은 노트를 쓰고, 원시 추론을 삭제함. 그래서 **피크 메모리가 2~3배 줄고 처리량이 거의 두 배**가 됨.

여기서 가져갈 게 둘.

- 이건 오케스트레이션을 덧붙인 게 아니라 **평범한 파인튜닝으로 학습된 스킬**임
- 지워진 추론이 완전히 사라지지는 않음. **모델 안에 그림자가 남고**, 노트만으로 컨텍스트를 재구성하면 **정확도 15포인트**를 잃음. 잊는 건 삭제가 아니고, 기억하는 건 저장만이 아님

## Anthropic, 보관하는 것을 통제하기

**지울 수 있는 파일에 메모리를 둠.** Anthropic의 방식은 거의 지루한데, 그게 요점임. 메모리를 파일시스템의 파일로 만들어서 에이전트가 이미 쓰는 도구로 읽고 씀. 중요한 이유는 파일이 가능하게 하는 것들 전부임. 내보내기, 검사, 그리고 **에이전트가 정확히 무엇을 보유하는지에 대한 프로그래밍 통제.** 열어서 편집할 수 없는 저장소는 통제하지 못하는 저장소임.

**범위 지정, 감사, 롤백.** 잘못된 기억은 한 번 실패하는 게 아니라 그걸 읽는 **모든 미래 세션으로 지속됨.** 그래서 통제는 메모리 위에 얹는 레이어가 아니라 설계 자체임.

누가 읽고 누가 쓰는지 범위를 정하고, 무엇을 어디서 배웠는지 감사 추적을 남기고, 손을 넣어 지울 권한을 유지함. 제대로 하면 측정 가능함. 이렇게 만든 팀들이 **1차 오류를 97% 줄이고 검증을 약 1/3 빠르게** 했음. 학습 과정이 계속 관측 가능했기 때문.

## Nvidia, 하드웨어에서 살아남기

**메모리를 텍스트가 아니라 KV 캐시로 읽음.** 알고리즘을 걷어내면 모든 메모리 결정이 GPU에 떨어짐. 전체 히스토리를 컨텍스트에 두는 건 느린 게 아니라 **제곱**이고(full-attention prefill 기준. sparse·linear attention이나 sliding window 모델은 다름), 세션 안에서 살려주던 prefix 캐싱은 **세션을 넘으면 붕괴**함.

그 압력 전부가 희소 자원 하나에 몰림. HBM 안의 **KV 캐시**. Memory Engineer는 메모리를 HBM 대역폭, GPU 사용률, 초당 토큰, 해제된 KV 슬롯으로 읽음. 온갖 영리한 기법 아래의 진짜 통화가 캐시니까.

**구축을 백그라운드 잡으로 다룸.** 구축은 거의 순수 prefill임. 길게 읽고 짧게 쓰니까 백그라운드 인덱싱 잡처럼 행동함. 라이브 쿼리와 같은 곳에 두면, 큰 쓰기 작업이 하필 사용자 쿼리가 도착할 때 스케줄러를 멈춰 세움. 레이트 리밋을 걸거나 배치로 묶거나 미루고, **지연시간에 민감한 경로에서 떼어놓음.**

## 다치지 않게 만들기

**각 패스를 먼저 손으로 증명함.** 스케줄 걸기 전에 한 번 돌림. 실제 히스토리를 에이전트에 가리키고, 사실과 스킬을 뽑고, 그 사이 모순을 플래그하고, 그것들을 최신으로 유지하는 비용을 매기게 함. 출력이 **정말로 결정을 바꾸면** 스케줄을 얻을 자격이 있음. 노트 세 개에 대고 돌리는 메모리 시스템은 없는 연결을 환각하고, 그걸 무시하도록 사람을 훈련시킴.

**저장소가 커지기 전에 망각 정책을 넣음.** Stanford가 테스트한 시스템 중 **기본적으로 가지치기나 망각을 하는 건 하나도 없었음.** 그래서 발자국은 자라기만 하고, **100만 토큰 지점에서 시스템 간 최대 9배 차이**가 났음. 에이전틱 시스템은 저장소 자체가 커지면서 복리로 붙음.

> 오래 사는 에이전트를 파산시키는 건 시작 크기가 아니라 **성장 기울기**임.

dedup, 통합, 명시적 망각 규칙을 볼륨이 커지기 전에 넣음. 그리고 **모순을 자동 병합하지 않음.** 서로 어긋나는 두 기억은 다른 맥락에서 둘 다 맞았을 수 있음. 시스템은 드러내고, 결정은 사람이 함.

## 출하 순서

1. **쓰기 경로를 먼저** 만들어 사실과 스킬을 저장하고, 몇 주 채워서 실제 재료가 쌓이게 함
2. **모순 감지를 손으로** 몇 번 해보고, 충돌이 놀랍기만 하면 스케줄을 걺
3. **망각·유지 정책을 볼륨이 오르기 전에** 추가
4. **하드웨어 레이어는 마지막에**, 볼륨이 실제로 생긴 뒤에. 구축 배치, 검색 상한, KV 캐시 감시

첫날에 전부 스케줄 걸지 않음. 수동 실행 하나를 신뢰할 수 있게 만들고, 감싸고, 그다음 자동화함.

## 결론

모든 메모리 시스템이 같은 걸 약속함. 절대 잊지 않고, 패턴을 알아채고, 먹인 모든 것의 살아 있는 저장소가 된다고. 좋음. 그게 이 일의 **쉬운 절반**, 기억하기임.

Memory Engineer는 나머지 절반을 함. "여기 내가 보관한 전부"가 아니라 **"여기 내가 보관하지 않기로 한 것, 증류한 것, 썩기 전에 가지친 것, 다음 배치가 들어가게 비운 것."**

> 저장하는 사람은 시스템이 **기억하는 것**을 최적화하고, Memory Engineer는 시스템이 **잊는 것**을 최적화함. 그게 전환의 전부임.

## 원문이 밝힌 출처

Stanford의 *Agent Memory: Characterization and System Implications*, Microsoft Research의 *PlugMem*과 *Memento*, Anthropic의 *Built-in Memory for Claude Managed Agents*. 하드웨어 프레이밍은 Stanford와 Memento 논문의 H100, vLLM, B200 설정에서 가져왔다고 함.

## 메모

- 수치가 구체적인 게 이 글의 강점인데, 동시에 검증 포인트임. 47배, 15포인트, 97%, 9배 같은 숫자는 원문이 밝힌 논문에서 직접 확인해야 인용할 수 있음. 이 문서는 글이 주장한 대로 옮겼을 뿐임
- Anthropic의 "파일로 메모리" 방식이 가장 지루하면서 가장 실용적임. 지금 당장 따라 할 수 있는 유일한 항목이기도 함
- "정확도와 정답당 비용을 항상 같이 인용한다"는 규칙은 메모리 시스템뿐 아니라 모든 LLM 파이프라인 평가에 그대로 적용됨
