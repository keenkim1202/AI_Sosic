## 요약

**나흘 치 네 릴리스에 "에이전트가 내 파일을 망가뜨리던 것" 수정이 19건** 들어 있음. 묶어 보면 성격이 하나로 모임. **설정 파일을 읽지 못했을 때 그것을 빈 설정으로 다루고 그대로 저장했다**는 것임. `~/.claude.json` 이 네트워크 지연이나 파일 락으로 읽히지 않으면 **저장 과정에서 비워지고 기본값으로 리셋**됐고, 프로젝트의 scheduled tasks 파일이 읽히지 않으면 태스크 하나를 저장하는 것이 **그 프로젝트의 다른 태스크를 전부 지웠음**. `claude mcp add --scope project` 는 `.mcp.json` 의 **`$schema` 나 다른 도구의 최상위 키를 지웠고**, `/terminal-setup` 은 블록 주석이 든 VS Code `settings.json`·`keybindings.json` 을 깨뜨리면서 **성공했다고 보고**했음.

두 번째 계열은 더 고약함. **파괴적 동작이 화면에 파괴적으로 보이지 않았음.** 파일을 지우거나 덮어쓰는 Bash 명령(`find -delete`, `cat a > b`, `sort -o`)이 **트랜스크립트에 검색이나 읽기로 요약**되고 있었고, `claude purge` 는 stdout 이 리다이렉트되면 프롬프트를 숨겨서 **보이지 않는 Enter 한 번으로 프로젝트 데이터가 지워질 수 있었음**. 승인하는 사람에게 레이블이 거짓이면 판정 정확도를 올릴 방법이 없음. 이 저장소의 [사람이 에이전트 명령 승인에서 위협 3건 중 1건을 놓친다](./2026-08-05-agent-approval-miss-rates.md)가 측정한 실패 지점이 정확히 여기임.

세 번째로, 안전망 쪽에도 수정이 몰렸음. **`/rewind` 수정이 네 릴리스에 5건**이고 그중 둘은 조용히 실패하던 것임. 복원 못 한 파일이 있어도 **아무 말 없이 닫히거나** 셸 명령이 바꾼 파일을 두고 **"No code changes"** 라고 말했음. VS Code 쪽은 포크된 대화에서 **한 턴 더 되돌려 그 턴에 만든 파일을 지웠음**. 그래서 결론은 버전 올리라는 것으로 끝나지 않음. **되돌리기를 복구 수단으로 계획에 넣으면 안 되고, 커밋만이 안전망임.**

## 읽을 수 없는 설정을 빈 설정으로 다룬 쪽

계열 분류는 이 문서가 한 것임. 릴리스 노트는 항목을 묶어 주지 않고 평평한 목록으로 적음.

| 대상 파일 | 일어난 일 | 릴리스 |
|---|---|---|
| `~/.claude.json` | 네트워크 지연이나 파일 락으로 읽히지 않을 때 **저장 중에 비워지고 기본값으로 리셋**됨 | 2.1.329 |
| 프로젝트의 scheduled tasks 파일 | 파일을 읽을 수 없을 때 태스크 하나를 저장하면 **그 프로젝트의 다른 저장된 태스크가 지워짐** | 2.1.328 |
| 같은 파일 | 오타가 든 태스크는 **그 파일이 다음에 저장될 때 삭제**됨 | 2.1.328 |
| `.mcp.json` | `claude mcp add`·`claude mcp remove --scope project` 가 **다른 최상위 키를 지움**. `$schema` 와 다른 도구의 `servers` 가 예로 적혀 있음 | 2.1.327 |
| VS Code `settings.json`·`keybindings.json` | `/terminal-setup` 이 **블록 주석 주변을 깨뜨림**. `keybindings.json` 에 닫히지 않은 문자열이 있으면 **성공했다고 보고하면서 Shift+Enter 바인딩을 잃음** | 2.1.329 |

같은 계열의 정책 변경이 하나 붙었음. `claude mcp add --scope project` 가 `.mcp.json` 이 **`mcpServers` 키 없이 최상위에 서버를 적어 둔 경우 덮어쓰지 않고 멈춤**. MCP 문서의 모든 `.mcp.json` 예시는 서버를 `mcpServers` 아래 두고, `claude mcp add-json` 만 그 안쪽 객체를 받음. 즉 래퍼 없이 적힌 파일은 **Claude Code 가 쓰는 포맷이 아닌데 덮어쓸 대상으로는 골라졌던** 것임.

읽기 실패를 다루는 방향이 이번에 바뀐 것도 같이 보면 좋음. 2.1.329 는 **하위 폴더나 worktree 의 `.claude/settings.local.json` 이 읽히지 않거나 깨져 있을 때 권한 룰 추가가 "Couldn't save this change" 를 거짓으로 띄우던 것**을 고쳤고, 재개 시 **파일이 멀쩡한데도 손상된 파일 탓을 하던 안내문**도 고쳤음. 읽기 실패를 조용히 삼키는 쪽과 엉뚱한 파일을 지목하는 쪽이 같은 릴리스에 같이 수정된 셈임.

## 지워지면 git 이 못 돌려주는 쪽

| 일어난 일 | 릴리스 |
|---|---|
| Remote Control 에서 **worktree 모드로 서버를 멈추면 도는 세션의 git-ignored 파일이 지워짐.** 릴리스 노트가 예로 든 것이 `.env` | 2.1.327 |
| 재전송된 파일이 **Claude 가 바꿔 둔 사본을 덮어씀.** 이제 사본이 `.kept-` 폴더로 옮겨지거나 새 파일이 저장되지 않음 (Linux 의 Remote Control·클라우드 세션, 피처 플래그가 로드되지 않은 경우) | 2.1.326 |
| `/export` 가 **기존 파일을 묻지 않고 덮어씀.** 이제 다이얼로그가 묻고 `/export <name>` 은 파일을 남기고 `/export` 를 돌리라고 말함 | 2.1.327 |
| 같은 `/export` 가 **이름을 비우면 `.txt` 라는 이름의 파일을 씀** | 2.1.328 |

첫 줄이 이 표에서 제일 중요함. **git-ignored 파일은 정의상 git 이 복구해 주지 않음.** `.env`, 서명 프로파일, 로컬 `xcconfig` 같은 것을 worktree 안에 두고 돌리던 구성이면 복구 경로가 없었다는 뜻임.

정책 변경도 둘 붙었음. `ExitWorktree` 가 **저장 안 된 작업이 있을 수 있는 worktree 를 제거하기 전에 묻게** 됐음. don't-ask 모드이거나 답할 사람이 없으면 거부되고, allow 룰·auto·bypass permissions 모드가 허용하면 그냥 진행됨. 그리고 플러그인 삭제가 **MCP 번들(`.mcpb`, `.dxt`)에서 풀어낸 파일까지 지우게** 됐고(다른 플러그인이 같은 번들을 쓰면 남김), 마켓플레이스 제거 질문이 **그 플러그인들의 설정과 저장 데이터가 지워진다**고 말하게 됐음.

## 파괴적 동작이 파괴적으로 보이지 않던 쪽

- **지우고 덮어쓰는 Bash 명령이 트랜스크립트에 검색이나 읽기로 요약됨.** 릴리스 노트가 `find -delete`, `cat a > b`, `sort -o` 셋을 예로 적음 (2.1.326). 승인 프롬프트를 통과한 뒤의 기록 쪽이지만, 세션을 되짚어 무엇이 일어났는지 세는 작업이 틀린 레이블 위에서 돌고 있었다는 뜻임
- **`claude purge` 가 stdout 이 리다이렉트되면 프롬프트를 숨김.** 보이지 않는 Enter 한 번으로 프로젝트 데이터가 지워질 수 있었음. 이제 프롬프트가 터미널에 뜸 (2.1.326)
- **삭제 질문 위에 글자를 타이핑하면 선택이 움직임.** `/sandbox` 와 `/permissions` 의 삭제 질문에서 났음 (2.1.326)
- 같은 방향의 정책 변경: **대부분의 권한 프롬프트에서 방향키가 마지막 답을 넘어 감싸지 않고 No 에 멈춤**. 마지막 답 다음 번호를 누르면 No 로 감 (2.1.327)

마지막 항목이 성격이 다름. 수정이 아니라 **잘못 누를 때 기본적으로 거부 쪽으로 떨어지게** 바꾼 것임. 위 셋이 전부 "사람이 본 화면과 실제 동작이 달랐다" 계열인데, 그 대응으로 화면을 정확하게 만드는 것 말고 **틀려도 덜 다치는 방향**을 같이 넣은 셈임.

## `/rewind` 는 안전망이 아님

네 릴리스에 `/rewind` 수정이 5건임. 묶어 읽으면 **복원이 실패해도 그렇다고 말하지 않던 것**이 둘이고, 실제로 파일을 잃던 것이 둘임.

| 일어난 일 | 릴리스 |
|---|---|
| `/branch` 를 두 번 돌린 뒤 느린 백업 복사가 아직 도는 중이면 **일부 파일만 복원**함 | 2.1.326 |
| 셸 명령이 복원할 수 없는 파일을 바꿨을 때 **"No code changes"** 라고 말함. 변경이 추적되지 않은 턴은 이제 **"Code changes unknown"** 으로 읽힘 | 2.1.326 |
| 긴 프롬프트가 **이후 파일 변경을 잃는다는 경고를 가림** | 2.1.326 |
| 복원하지 못한 파일이 있을 때 **아무 말 없이 닫힘** | 2.1.327 |
| VS Code 의 "Rewind code to here" 가 포크된 대화에서 **한 턴 더 되돌려 그 턴에 만든 파일을 지움** | 2.1.326 |

그리고 수정이 아닌 설계 선택이 하나 있음. 2.1.326 부터 **macOS·Linux·WSL 에서 샌드박스가 켜져 있으면 `/rewind` 가 일부 파일을 건드리지 않고 skipped 로 보고**함. 어떤 파일이 그 범위에 드는지는 릴리스 노트가 적지 않음. 샌드박스를 켜서 얻는 안전과 되돌리기 범위가 **서로 거래 관계**라는 뜻이고, 둘을 동시에 믿는 구성이 성립하지 않음.

## 조용히 내용이 바뀌던 둘

- **IDE diff 로 수락한 파일이 마지막 줄바꿈 없이 저장됨.** VS Code 에서 diff 를 저장해 편집을 수락하면 **BOM 도 잃음** (2.1.329)
- **NotebookEdit 이 노트북 파일의 마지막 줄바꿈을 지움** (2.1.327)

둘 다 diff 로는 거의 안 보이고 린터나 포맷 검사에서 뒤늦게 터지는 종류임. 프로젝트 파일을 에이전트가 직접 고치는 경로를 쓰고 있으면 바로 걸림.

## 범위 밖으로 둔 것

셀프호스트 러너 쪽에도 같은 계열 수정이 넷 있음. `--use-anthropic-git-proxy` 가 **`GIT_CONFIG_GLOBAL` 이 가리키는 비어 있지 않은 디렉터리를 시작할 때 지우던 것**(2.1.327, 이제 남기고 변수를 무시하고 경고함), 일시적 디스크 오류 뒤 **보관 클론의 오브젝트·ref 와 그곳에만 있던 커밋이 삭제되던 것**(2.1.328, 이제 시작이 실패함), `--push-outcome-on-release` 가 **git 호스트에서 세션의 브랜치를 지우던 것**(2.1.329), 그리고 **손상된 `.claude.json` 이 `--trust-workspace false` 에서 이후 모든 시작을 실패시키던 것**(2.1.328).

개인 머신에서 돌리는 구성과는 상관이 없어서 위 집계 19건에는 넣지 않았음. 다만 **같은 "읽기 실패와 삭제" 계열이 배포 경로에도 있다**는 것은 적어 둘 값어치가 있음.

## 지금 할 것

- **설정 파일을 git 에 넣어라.** `.mcp.json`, `.claude/settings.json`, 프로젝트의 VS Code `settings.json`·`keybindings.json`. 위 손실 5건 중 네 건은 git 에 들어 있으면 `git diff` 로 즉시 보이고 복구됨. `~/.claude.json` 은 홈에 있어 그 보호를 못 받으므로 따로 백업하는 쪽이 맞음
- **worktree 안에 git-ignored 파일을 두고 돌리지 마라.** `.env` 류는 worktree 바깥에 두고 심링크나 환경변수로 넘기는 쪽이 복구 경로가 있음
- **`/rewind` 를 되돌리기 계획으로 쓰지 마라.** 샌드박스가 켜져 있으면 범위가 줄고, 범위가 어디까지인지 문서가 없음. 에이전트에게 긴 작업을 맡기기 전에 커밋하는 것이 유일하게 믿을 수 있는 수단임
- **2.1.329 이상으로 올려라.** 다만 2.1.329 는 **이전 버전이 저장한 scheduled task 대부분을 새로 로그인한 세션에서 다시 스케줄하게** 만듦(그 태스크 자신의 세션을 `--resume` 하면 돈다고 적혀 있음). 올리기 전에 저장해 둔 태스크 목록을 따로 적어 두는 쪽이 안전함
