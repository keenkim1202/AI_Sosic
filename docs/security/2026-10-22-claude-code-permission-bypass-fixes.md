## 요약

**2.1.309 한 릴리스에 권한 검사·샌드박스·worktree 격리를 빠져나가던 동작 수정이 13건** 들어 있음. 기능 릴리스에 섞여 한 줄씩 적혀 있어서 그냥 읽으면 버그 수정으로 보이는데, 묶어 보면 성격이 같음. **셸 문자열을 파싱해서 허용·거부를 정하는 층이 셸 문법과 파일시스템의 실제 모양에 번번이 졌다**는 것임. 샌드박스된 Bash 명령이 **매 명령 전에 셸 startup 파일을 샌드박스 밖에서 실행**하고 있었고, `denyWrite` glob은 **심링크를 지나 도달한 경로의 실제 위치에 적용되지 않았으며**, `Edit(path)` deny 룰은 **서브셸을 품은 명령의 리다이렉트**를 막지 못했음.

같은 저장소의 보안 권고 **35건**(2025-06-23 ~ 2026-10-13)과 대조하면 이번 13건은 새 계열이 아님. 심링크로 쓰기 보호를 우회하는 권고가 이미 **6건**, 셸 문법으로 명령 검사를 우회하는 권고가 **8건** 있었음. 그래서 이 문서의 결론은 버전 올리라는 것 하나로 끝나지 않음. **로컬 권한 규칙은 사고를 줄이는 완화 수단이고, 신뢰 경계로 쓰면 계열째로 재발하는 쪽에 베팅하는 것임.**

그리고 보안 정보가 어디에 먼저 뜨는지가 이 릴리스에서 드러남. 2026-10-05에 공개된 권고는 **2.1.129**에서 고쳐진 것이고 그 버전은 **2026-05-06** 릴리스임. 권고는 수정보다 **약 5개월** 뒤에 나왔음. 릴리스 노트를 보안 공지로 읽어야 하는 이유가 이것임.

## 2.1.309에서 닫힌 구멍

분류는 이 문서가 한 것임. 릴리스 노트는 항목을 묶어 주지 않고 평평한 목록으로 적음.

| 계열 | 수정된 동작 |
|---|---|
| 샌드박스 바깥 실행 (1건) | 샌드박스된 Bash 명령이 **매 명령 전에 셸 startup 파일을 샌드박스 밖에서** 실행 (macOS·Linux) |
| 심링크 (2건) | macOS 샌드박스 `denyWrite` glob이 패턴의 폴더를 심링크로 지나갈 때 **경로의 실제 위치에 적용되지 않음**. 설정 디렉터리를 심링크로 지나 도달하면 **profile store 쓰기 보호가 적용되지 않음** |
| 설정 변조 (2건) | 샌드박스된 명령과 **자동 승인된 편집이 `--mcp-config`로 넘긴 MCP 설정 파일 자체를 수정**할 수 있었음. print·SDK 세션에서 **비활성화한 MCP 서버가 나중에 뜬 권한 프롬프트로 다시 연결**됨 |
| 셸 문법 (3건) | Bash 권한 검사가 **리다이렉트가 열리지 않을 수 있는 명령이 설정한 변수**를 신뢰함. `cd`가 감싸이거나 접두사가 붙은 복합 명령은 git을 실행해도 **프롬프트가 뜨지 않음**(맨 `cd`일 때는 떴음). `Edit(path)` deny 룰이 **서브셸을 함께 품은 일부 명령의 Bash 리다이렉트**를 그 경로로 허용함 |
| worktree 격리 (2건) | 격리 세션이 **로케일 접두사가 붙은 명령**을 통과시킴. zsh 격리 세션이 **산술 명령 일부**를 통과시킴 |
| 수명 (1건) | Linux에서 **백그라운드 명령이 세션보다 오래 살면 샌드박스 쓰기 거부가 풀림** |
| 훅 (1건) | PowerShell에서 도는 훅이 **종료 코드 2로 차단하지 못함**. `"shell": "powershell"` 훅은 Git for Windows가 없으면 **fail open** |
| Windows 권한 검사 (1건) | PowerShell 권한 검사가 현재 디렉터리를 대상으로 하면서 인자가 더 붙은 `Set-Location`·`cd` 일부를 **자동 승인**함 |

하루 뒤 2.1.310이 훅 쪽을 한 번 더 고쳤음. **Git Bash가 없고 훅 커맨드가 인용된 문자열뿐일 때 `PreToolUse`와 `PermissionRequest` 훅이 툴 호출을 통과시키던 것**임. 훅을 게이트로 쓰는 구성에서 **게이트가 조용히 열려 있던** 사례가 이틀에 두 건 나온 셈임.

같은 릴리스에 사람 쪽 수정도 하나 있음. **파일 읽기 권한 프롬프트가 심링크의 도착지를 보여주지 않던 것**을 고쳤음. 승인 화면에 무엇을 승인하는지가 안 적혀 있었다는 뜻이고, 이건 [사람이 에이전트 명령 승인에서 위협 3건 중 1건을 놓친다](./2026-08-05-agent-approval-miss-rates.md)가 측정한 바로 그 실패 지점임. 그쪽 결론은 사람의 판정 정확도를 올리려 하지 말라는 것이었는데, 프롬프트가 도착지를 숨기고 있었으면 정확도를 올릴 방법이 애초에 없었음.

## 같이 바뀐 기본값

수정이 아니라 **정책을 조인 것**이 넷임. 업데이트하면 스크립트가 깨질 수 있는 쪽이라 따로 적음.

- 설정으로 샌드박스에서 제외한 명령은, **샌드박스가 켜져 있지만 실행되지 못하는 상태**에서 write-list 경로에 쓰려면 묻게 됨. 샌드박스 없이 그냥 돌리는 폴백은 거부됨
- bypass permissions 모드의 위험한 `rm`·`rmdir` 프롬프트가 **Desktop 앱과 VS Code에서는 즉시 거부**로 바뀜. 재작성 힌트를 주고 무인 세션이 멈추지 않게 하는 쪽을 택함
- `claude ultrareview`가 **workspace trust를 요구**함. 터미널에서는 묻고 아니면 거부함. 스크립트는 `--trust-workspace`를 넘기거나 `CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1`을 씀
- `sed -i`가 **표준 Bash 프롬프트를 받고 적힌 대로 실행**됨. 파일 편집 미리보기를 시뮬레이션하지 않고, 다른 Bash 편집처럼 `/rewind`로 복원되지 않음

마지막 항목은 이력이 있음. 보안 권고에 **"Sed Command Validation Bypass Allows Arbitrary File Writes"**(2025-11-20)와 **"Command Injection via Piped sed Command Bypasses File Write Restrictions"**(2026-02-06)가 따로 올라와 있음. `sed`를 편집 도구로 흉내내 특별 취급하던 구조가 두 번 뚫린 뒤, 특별 취급을 걷고 평범한 Bash 명령으로 되돌린 것으로 읽힘. **우회 가능한 똑똑한 검사보다 단순한 프롬프트가 낫다**는 판단임.

**4년치가 아니라 16개월치임.** 그리고 분류 가능한 것만 세도 22건이 이 네 계열에 들어감. 하나씩은 평범한 버그로 보이지만, 묶으면 "셸 문자열을 읽어서 안전 여부를 판정한다"는 설계가 계속 같은 방식으로 지는 중임.

실무에서 가져갈 것은 둘임.

1. **권한 규칙과 샌드박스를 다층 방어의 한 겹으로만 쓸 것.** `deny` 룰에 적어 뒀다는 사실이 그 경로가 안전하다는 뜻이 아님. 진짜 경계는 OS 샌드박스, 컨테이너, 계정 분리, 자격증명을 그 머신에 두지 않는 것임
2. **버전 고정이 보안 설정의 일부임.** 팀 이미지나 CI 러너에 Claude Code 버전을 박아 두고 자동 업데이트를 끈 환경이 이 13건에 가장 오래 노출됨. [팀 공유 AI 하네스 만들기](../agents/2026-08-10-hq-team-ai-harness.md)가 설정을 팀 기본값으로 배포하는 경로를 다루는데, 같은 경로로 버전 갱신도 같이 나가야 함

## 짚어야 할 것

- **릴리스 노트 문언만 읽었고 재현하지 않았음.** 각 항목이 실제로 어디까지 악용 가능했는지, 즉 임의 파일 쓰기까지 갔는지 프롬프트 한 번 건너뛴 수준인지는 노트에 없고 **확인할 수 없었음**
- **13건이라는 수와 계열 분류는 이 문서가 한 것임.** 릴리스 노트는 분류하지 않고 평평한 목록으로 적음. 어디까지를 "권한·샌드박스" 성격으로 볼지에 따라 수가 달라짐
- 영향받는 버전 범위가 없음. 각 동작이 **언제부터 있었는지** 노트에 적혀 있지 않아 노출 기간을 계산할 수 없었음
- 권고 목록에 제목이 거의 같은 심링크 권한 우회 건이 **2025-10-03과 2026-02-06 두 번** 올라와 있음. 재공개인지 같은 계열의 별건인지 **확인할 수 없었음.** 위 표의 심링크 6건은 둘을 별건으로 센 값임
- 권고 셋 중 하나(2026-10-13, 악성 git 실행 파일 경로)는 패치 버전이 **`1.8089.0`**으로 다른 번호 체계임. CLI가 아닌 다른 구성요소로 보이나 확인하지 못해 위 시차 표에서 뺐음
- 저장소에 `CHANGELOG.md`가 있지만 **항목에 날짜가 없음.** 이 문서의 날짜는 전부 `gh api`로 받은 릴리스 `published_at`(UTC) 기준임

## 유효기간

**2026-10-26 확인 기준이고 최신 릴리스는 2.1.310**임. 이 릴리스는 하루에 한두 개씩 나오므로 버전 번호는 읽는 시점에 이미 낡았다고 보는 게 맞음. 수정 목록 자체는 시점이 박힌 기록이라 낡지 않지만, 계열 집계는 다시 세야 함. 다시 볼 때는 `gh api repos/anthropics/claude-code/security-advisories`로 권고를 새로 받아 **이번 13건에 번호가 붙었는지**, 그리고 **네 계열에 또 쌓였는지**를 보는 편이 빠름. 릴리스 노트 쪽은 `gh api repos/anthropics/claude-code/releases`로 받아 `Fixed ... permission`·`sandbox`·`isolation` 줄만 훑어도 대부분 잡힘.
