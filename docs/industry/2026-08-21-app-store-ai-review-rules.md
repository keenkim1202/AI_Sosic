## 요약

앱에 AI 기능을 붙이면 프레임워크 문제보다 **심사 조항**에 먼저 걸림. 핵심은 **5.1.2(i)**임. 개인정보를 서드파티 AI에 보내려면 **어디로 가는지 명확히 공개하고 명시적 동의를 먼저 받아야 함.** 약관이나 개인정보처리방침에 묻어두는 건 공개로 안 쳐줌. 여기에 **남이 만든 챗봇을 앱 안에 얹을 때만** 걸리는 **4.7 묶음**, 실행 코드 반입을 막는 **2.5.2**, 연령등급 **2.3.6**이 따라옴. 2026-06-08자 개정으로 **개발자 프로그램 라이선스 계약(DPLA)에 AI·ML 항목이 신설**돼서 Foundation Models를 쓰면 심사 지침 말고 계약서도 봐야 함.

## 5.1.2(i), 서드파티 AI로 개인정보를 보낼 때

조항 원문에서 이 문서에 해당하는 문장은 이것임.

> "You must clearly disclose where personal data will be shared with third parties, including with third-party AI, and obtain explicit permission before doing so."

같은 조항이 이어서 붙이는 조건들이 더 무거움.

- 데이터를 **어떻게, 어디서** 쓰는지에 대한 정보 접근 경로를 제공해야 함
- 앱에서 수집한 데이터를 서드파티와 공유하는 건 **앱 개선 또는 광고 게재 목적으로만** 허용됨. DPLA 준수가 전제임
- 동의 없이 공유하거나 데이터 프라이버시 법을 안 지키면 **판매 중단에 더해 개발자 프로그램에서 제거**될 수 있음

실무로 번역하면 이렇게 됨.

| 해야 하는 것 | 하면 안 되는 것 |
|---|---|
| 어떤 **제공자**에게 어떤 **데이터**가 가는지 이름을 대고 밝히기 | 개인정보처리방침·이용약관 안에만 적어두기 |
| 전송 **전에** 명시적 동의를 받기 | 기능을 켜면 동의한 것으로 간주하기 |
| 나중에 **철회**할 경로를 두기 | 동의를 한 번 받고 끝내기 |

⚠️ **온디바이스 처리와 서버 전송을 갈라야 함.** Apple의 온디바이스 모델만 쓰면 이 조항의 "서드파티 공유"에 해당하지 않지만, OpenAI·Anthropic·Google 같은 외부 API를 호출하는 순간 해당됨. Private Cloud Compute는 Apple 자신의 인프라라 서드파티가 아님. 다만 5.1.2(i)의 판단 기준은 **개인정보가 어디로 나가느냐**지 어느 SDK를 쓰느냐가 아니므로, 프롬프트에 사용자 데이터를 실어 보내는 모든 경로를 목록으로 만들어두는 편이 안전함.

## 4.7, 챗봇을 이름으로 지목하는 조항

4.7의 제목 자체가 "Mini apps, mini games, streaming games, **chatbots**, plug-ins, and game emulators"임. 다만 **적용 범위를 조항 첫 문장이 먼저 좁힘.**

> "Apps may offer certain software that is **not embedded in the binary**, specifically HTML5 and JavaScript mini apps and mini games, streaming games, chatbots, and plug-ins... You are responsible for all such software offered in your app, including ensuring that such software complies with these Guidelines and all applicable laws."

즉 4.7이 겨냥하는 건 **앱이 담아 제공하는, 바이너리에 내장되지 않은 소프트웨어**임. 갈라 보면 이렇게 됨.

| 만드는 것 | 4.7 해당 |
|---|---|
| 서드파티나 사용자가 만든 **챗봇을 앱 안에서 골라 쓰게 하는** 구조, 미니앱·플러그인 형태로 얹은 대화형 소프트웨어 | 해당 |
| 앱이 직접 구현한 네이티브 대화 기능. 원격 LLM API를 앱 코드에서 호출하는 경우 포함 | **해당 아님** |

⚠️ **네이티브 챗봇 기능을 만들면서 4.7의 요구를 자동으로 떠안을 필요는 없음.** 그 경우는 5.1.2, 1.2, 2.3.6 같은 조항이 각자의 조건으로 따로 걸리는 것이고, 4.7의 플랫폼형 요구(필터·신고·차단·연령 게이팅 일괄 적용)가 그대로 옮겨오지 않음. 반대로 앱 안에 다른 곳의 챗봇을 얹는 순간 아래가 전부 붙음.

하위 조항이 실제로 걸리는 지점임.

| 조항 | 요구 |
|---|---|
| **4.7.1** | 5.1 프라이버시 규칙 준수, **부적절 콘텐츠 필터 + 신고 수단 + 사용자 차단** 기능, 디지털 재화 판매 시 3.1 준수 |
| **4.7.2** | Apple 사전 허가 없이 **네이티브 플랫폼 API·기술을 그 소프트웨어에 노출하지 말 것** |
| **4.7.3** | **매 건마다 명시적 사용자 동의 없이** 데이터나 프라이버시 권한을 공유하지 말 것 |
| **4.7.5** | 앱 연령등급을 넘는 소프트웨어를 식별할 방법과, **확인되거나 신고된 연령 기반 접근 제한 장치** |

4.7.1의 필터·신고·차단 셋은 1.2(사용자 생성 콘텐츠)의 요구와 같음. **남이 만든 대화형 소프트웨어를 얹는 것을 사용자 생성 콘텐츠와 같은 급으로 다루는 게 이 지침의 태도**라고 읽는 편이 맞음.

네이티브 기능이라도 **사용자가 생성 결과를 공유하거나 봇을 만들어 남에게 노출할 수 있으면** 1.2가 독립적으로 걸림. 판단 기준은 "대화형이냐"가 아니라 **"다른 사용자에게 닿는 콘텐츠가 생기느냐"**임.

## 2.5.2, 모델 파일을 원격에서 받을 때

> "Apps should be self-contained in their bundles, and may not read or write data outside the designated container area, nor may they download, install, or execute code which introduces or changes features or functionality of the app, including other apps."

온디바이스 모델을 앱 번들에 넣지 않고 **런타임에 내려받는 설계**를 잡고 있으면 이 조항을 먼저 확인해야 함.

⚠️ **모델 가중치가 여기서 말하는 "code"에 해당하는지는 조항 문언만으로 판단이 안 됨.** 확인하지 못했음. 실행 그래프를 포함하는 컴파일된 모델 번들과 순수 가중치 파일이 같은 취급인지가 갈림길인데 지침이 그 구분을 하지 않음. 다운로드 방식을 전제로 설계 중이면 심사 전에 문의로 확인하는 게 맞음.

## 나머지 걸리는 곳

- **1.2 사용자 생성 콘텐츠**: 필터, 신고, 차단, 공개 연락처. 생성형 대화 기능은 사실상 이 요구를 그대로 받음
- **1.2.1(a) 크리에이터 콘텐츠**: 앱 연령등급 초과 콘텐츠 식별 방법과 연령 기반 제한 장치
- **2.3.6 연령등급 정확성**: App Store Connect 연령등급 문항을 정직하게 답할 것. 잘못 매기면 **규제 기관 조회**로 이어질 수 있다고 지침이 직접 적음
- **5.1.2(ii)**: 한 목적으로 수집한 데이터를 **추가 동의 없이 다른 목적으로 재사용 금지.** 기존 서비스 로그를 모델 학습·평가에 돌리려는 계획이 여기 걸림
- **5.1.2(vi)**: HealthKit, HomeKit, ARKit, 카메라·사진 API에서 얻은 데이터는 **마케팅·광고·용도 기반 데이터 마이닝에 사용 금지.** 서드파티 경유도 포함

## 개발자 프로그램 라이선스 계약의 AI 조항

2026-06-08자 개정에서 심사 지침이 아니라 **계약서** 쪽이 바뀜.

| 조항 | 개정 내용 (Apple 공지 요약 기준) |
|---|---|
| **3.3.11** | AI·머신러닝 기술을 새 하위 조항으로 묶음 |
| **3.3.11(A)** | **Foundation Models 프레임워크 사용 요건** 갱신 |
| **3.2(h)** | **Apple 모델 사용·접근 조건** 갱신 |

즉 Foundation Models로 기능을 만들면 지침만 보고 끝낼 수 없음. ⚠️ 다만 **위 표는 Apple 공지의 요약 문장을 옮긴 것이고 계약서 전문은 확인하지 못했음.** 실제 문언은 개발자 계정에서 DPLA 본문을 열어 확인해야 함.

같은 날 심사 지침 쪽 개정은 AI와 무관했음. 아동·청소년 안전 가이드, 1.2 책임 문단 신설, 4.3(a)/(b) 예시 추가, 4.5.3 Live Activities 스팸 금지였음.

## 체크리스트

앱에 AI 기능을 넣기 전에 이 순서로 훑으면 됨.

1. 프롬프트·첨부로 **밖으로 나가는 데이터** 전부 목록화. 온디바이스 / PCC / 서드파티 셋으로 분류
2. 서드파티가 하나라도 있으면 **제공자 이름과 데이터 항목을 명시한 동의 화면**과 철회 경로 설계 (5.1.2(i))
3. **남이 만든 챗봇·미니앱을 얹는 구조인지** 확인. 맞으면 필터·신고·차단·연령 제한 넷이 붙음 (4.7). 네이티브 기능이면 대신 **생성 결과가 다른 사용자에게 닿는지**로 1.2 해당 여부를 판단
4. 기존 사용자 데이터를 학습·평가에 쓸 계획이면 **재사용 동의**를 따로 받을 것 (5.1.2(ii))
5. Health·Home·AR·사진 출처 데이터가 섞이면 **광고·마이닝 경로에서 분리** (5.1.2(vi))
6. 모델을 원격에서 받을 계획이면 **2.5.2 해당 여부를 먼저 확인**
7. Foundation Models를 쓰면 **DPLA 3.3.11(A), 3.2(h)** 본문 확인
8. App Store Connect **연령등급 문항 재검토** (2.3.6)

## 짚어야 할 것

- **5.1.2(i)의 서드파티 AI 문구 자체는 2025-11-13자 개정임.** 새 소식이 아니라 이미 적용 중인 규칙이고, 이 문서는 조항 전문을 확인해 정리한 것임
- **DPLA 3.3.11 계열은 Apple 공지의 요약만 확인했고 계약서 전문은 못 읽었음**
- 2026-08 중 App Review Guidelines 개정은 개발자 뉴스 목록에서 확인되지 않았음. 같은 달 공지는 EU 사업 조건 변경(2026-08-18)과 한국 연령등급 변경(2026-08-12)이었고 둘 다 AI와 무관함
- 심사 실무는 조항 문언보다 리뷰어 판단으로 갈리는 부분이 있음. 이 문서는 문언만 정리한 것이고 리젝 사례를 모은 게 아님

## 유효기간

**2026-08-21 스냅샷**임. App Review Guidelines는 상시 개정되는 문서라 조항 번호와 문언이 바뀔 수 있음. 다시 볼 때는 이 문서의 조항 번호로 원문을 열어 문언을 대조하고, [개발자 뉴스](https://developer.apple.com/news/)에서 그사이 개정 공지를 확인하는 편이 나음.
